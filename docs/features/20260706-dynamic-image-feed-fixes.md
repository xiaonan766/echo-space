# 动态页图片稿件显示修复

## 背景

图片稿件进入粉丝动态后，发现两个问题：

- 2026-07-02 这类已经跨周的动态，在 2026-07-06 查看时仍显示为“星期四”，容易误以为是本周动态。
- Redis 动态缓存只包含部分内容时，动态页会直接返回缓存结果并显示“已经到底”，导致更早的图片动态没有从数据库补出。

## 实现概要

- 调整 web 端通用时间格式：今天显示时分，昨天显示“昨天”，本周内显示星期几，早于本周的内容显示 `YYYY-MM-DD`。
- 调整动态 feed 缓存读取策略：Redis 缓存未读满 `pageSize + 1` 条时回源数据库，保证数据库中的旧图片动态仍能出现，并把回源结果写回缓存。

## 核心改动文件

- `echo-space-frontend-web/src/utils/Utils.js`
- `echo-space-backend/internal/service/web/dynamic_service.go`
- `echo-space-backend/internal/service/web/dynamic_service_test.go`

## 接口与数据变化

- 未新增接口。
- 未新增数据库字段。
- Redis 缓存结构不变，仍复用视频纯 ID 和图片 `image:<imageId>` 成员格式。

## 验证方式

- 后端运行 `go test ./...`。
- web 前端运行 `npm run build`。
- 手动验证动态页：2026-07-02 的动态在 2026-07-06 显示为具体日期，旧图片动态不会因缓存不完整而消失。

## 遗留风险

- 缓存不足一页时会回源数据库，优先保证动态列表完整性；极少量用户的空动态或少量动态场景会多一次数据库查询。
